# ShaveBuddy 交付路线图

状态：手动剃须刀 Android Demo 已实现并验证
日期：2026-10-03

## 当前交付：最小 Demo

用户已将首批范围收敛为 Android、本地、单件手动剃须刀。先交付可操作的核心循环，不要求先完成原有双端技术验证。这个范围调整不代表整个阶段 0 或正式 MVP 已验收。

本次范围：首次设置 → 今天记录/补记 → 月历与删除 → 刀片状态 → 更换与周期历史；可编辑目标、自然日日期规则、Room 持久化和系统深浅主题。实现与验证证据见 [Demo 验证记录](demo-verification.md)。

本次不做：电动剃须刀、多装备、通知、评分备注、记录编辑、导入导出、iOS、账号、网络与云同步。

## 下一步：Android 平台能力与可信度

- 至少一台 Android 真机验证设置、记录、更换、旋转、进程/设备重启；
- API 26 与不同系统版本回归，检查大字体、深色模式和屏幕适配；
- 第一次 schema 升级时添加 Room Migration 及旧数据迁移测试；
- WorkManager 唯一任务替换/取消，本地通知允许/拒绝与系统设置降级；
- 不申请精确闹钟权限，明确提醒时间允许系统浮动；
- 冻结正式发布 applicationId、分发渠道、签名与隐私说明。

只有上述证据齐备，才将 Demo 的平台决策扩展为正式 MVP 决策。无需 iOS 真机作为 Android 阶段的退出条件。

## 再下一步：完整 MVP

按实际使用反馈补齐：历史编辑、评分备注、多装备、设置和正式提醒、版本化 JSON 导出/恢复、无障碍与发布质量。导入需完整校验、摘要确认与事务回滚；通知副作用不影响已保存历史。

完整 MVP 成功标准仍以产品文档为依据，其中双端发布标准仅在启动 iOS 项目后适用，不能套用到当前 Android Demo。

## 小范围试用与 iOS 评估

先连续使用 2–4 周，观察记录入口、次数/天数价值、日历与更换习惯，再决定 iOS、备份、提醒的优先级。保留不采集埋点的产品原则。云同步、小组件、库存与商业化暂不进入开发。
