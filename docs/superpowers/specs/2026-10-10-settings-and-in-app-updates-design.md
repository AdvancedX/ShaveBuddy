# 设置页、应用内更新与日期标题布局设计

日期：2026-10-10  
状态：设计已确认；编码交由独立 Codex 线程，本文件未实施代码

## 背景与目标

目前 ShaveBuddy 是原生 Android Demo，使用 Kotlin、Jetpack Compose 和 Room。试用包通过 GitHub Releases 分发，用户每次都要在手机浏览器下载 APK 再打开安装。希望在 App 内点击一次「检查更新」，有新版本时自动下载，并交给 Android 系统覆盖安装。

App 也需要一个独立的「设置」页，容纳后续与单件装备无关的功能。现有「装备」页继续只管理剃须刀与刀片。

用户提供的真机照片显示，「今天」页顶部的大日期标题 `10月10日 星期六` 在插画旁边宽度不足时，把 `六` 单独换到下一行。本次一并调整标题排版。这个问题不在日历的星期栏。

## 已决定的范围

- 「今天」「日历」「装备」三个主页面右上角显示同一个设置图标。
- 点图标进入独立的「设置」页；从设置返回时回到原来的主页面和选中状态。设置页不显示底部三栏导航。
- 设置页首版只放「应用更新」区：当前版本、「检查更新」按钮、结果与下载进度。未来的备份、提醒等功能可以在此扩展，但本次不实现。
- 用户主动点击「检查更新」后才联网。发现较新版本时自动下载 APK；下载完成、通过校验后，打开 Android 系统安装界面。允许取消下载或在失败后重试。
- 不做启动时自动检查、后台定时更新、静默安装，也不添加账户或自建服务器。

## 页面与交互

```text
今天 / 日历 / 装备                      [设置图标]
                                           │
                                           ▼
                                  ←  设置
                                  ┌─────────────┐
                                  │ 应用更新     │
                                  │ 当前版本 …   │
                                  │ 检查更新     │
                                  │ 状态 / 进度  │
                                  └─────────────┘
```

设置页展示以下明确状态：

| 状态 | 页面反馈 |
| --- | --- |
| 未检查 | 当前版本和「检查更新」 |
| 查询中 | 加载状态，避免重复请求 |
| 已是最新 | 明确显示「当前已是最新版本」，仍可再次检查 |
| 找到更新 | 显示目标版本，立即开始下载 |
| 下载中 | 显示进度和取消入口；若服务器未给总大小，显示不确定进度 |
| 等待安装授权 | 解释需允许 ShaveBuddy 安装此来源的应用，跳转系统设置；返回后继续安装 |
| 准备安装 | 打开系统安装界面；若用户取消，保留「继续安装」入口 |
| 失败 | 用可理解的文案说明网络、文件或安装校验失败，并提供重试 |

Android 的安装确认由系统呈现，App 不能跳过。首次允许“安装未知应用”也由系统控制。拒绝授权或取消安装时，不卸载现有 App，不清除本地记录。

## 更新来源与版本规则

**更新源确定为公开的 `AdvancedX/ShaveBuddy` GitHub Releases**，因为现有试用 APK 已经从这里发布。App 请求 `https://api.github.com/repos/AdvancedX/ShaveBuddy/releases` 获取发布列表，再下载选中条目的 APK 附件；不在 App 内放 GitHub 令牌，也不从源码仓库分支直接生成安装包。发布新版本时，维护者仍需构建、使用原签名、提高 `versionCode`，并把 APK 上传为 Release 附件。

Releases 列表包含现有 `*-demo` 预发布版；不能使用 `releases/latest`，因为该接口排除预发布版。只考虑已发布、带有项目 APK 附件、符合 `v主版本.次版本.修订号[-demo]` 命名的条目。选择数值版本最高、且高于本机版本的候选版本；不按字符串字典序比较。

用户已确认继续使用 GitHub。它的优点是不必先维护另一套服务器或存储；限制是手机必须能访问 GitHub API 和 Release 附件。访问失败时显示明确的网络错误与重试入口，不把网络故障误报为“已是最新版本”，也不影响已有本地记录。本次不启用第二更新源，也不接受用户输入任意 APK 下载地址，以免出现版本先后和信任来源冲突。如果未来确需换源，仅替换发布元数据与下载地址的实现，并保留版本、摘要、包名与签名校验。

检查阶段只读取发布元数据。下载使用附件的 HTTPS 地址，写入 App 私有缓存，不需要存储权限。文件长度设置合理上限；下载中断时删除半成品。若 GitHub 提供 SHA-256 摘要，下载完成后必须匹配。接着读取 APK 元数据，确认：

1. `applicationId` 是 `com.shavebuddy.demo`；
2. APK 的 `versionCode` 高于当前已安装版本；
3. APK 签名证书与已安装 App 相同。

任何检查失败都不打开安装器，并删除无效文件。最后仍由 Android 安装器复核是否允许覆盖。

当前仓库中的 `0.1.2-demo` APK 与本机 Debug 构建的签名证书已核对一致；它们的包名为 `com.shavebuddy.demo`、`versionCode` 为 3。带更新功能的首个试用包应使用相同证书，版本号至少提升到 4，之后每次发布继续递增。不能随意换一台机器的默认 Debug 签名或用 CI 临时生成的 Debug 签名发布更新，否则系统会拒绝覆盖，且卸载重装会删除目前仅存于本机的记录。正式商店发布的身份和签名属于另一项发布决策。

**首次迁移：** 用户手机上已装的版本没有更新页面，因此仍需手动安装一次带此功能的 APK。之后，只要新版按上述规则发布到 GitHub Releases，用户即可在设置页完成下载和系统覆盖安装。发布新版 APK 本身仍需构建、签名并上传。

## 实现边界

- `ShaveApp` 管理主页面与设置页的切换，保留原主页面状态；顶部设置入口的触控区域和无障碍描述保持一致。
- `SettingsScreen` 只负责呈现版本、状态、操作和安装权限说明。
- 独立的更新状态持有者处理查询、下载、取消与重试，生命周期不依赖单个 Compose 重组，也不耦合剃须记录的 ViewModel。
- GitHub 发布列表读取、版本筛选和 APK 下载校验放在更新模块；版本选择使用可独立测试的纯逻辑。
- App 私有缓存中的 APK 通过 `FileProvider` 的 `content://` URI 临时授权给系统安装器。Manifest 增加联网和请求安装权限；不申请广泛文件访问权限。
- 网络超时、GitHub 限流、无可用 APK、下载损坏、存储不足、签名或版本不匹配分别落到可重试或明确失败状态。下载取消与进程退出时清理临时文件。

## 「今天」日期标题修复

现有顶部标题把完整日期作为单个可换行的 `Text`，右侧固定尺寸插画又压缩文字宽度，因此中文星期名称可能在任意字间断行。调整为日期部分（如 `10月10日`）与星期部分（如 `星期六`）两个完整的排版单元：宽屏可并排，当前照片所示宽度下星期整体换到第二行，绝不出现孤立的 `六`。在更窄屏幕或更大系统字体下，插画让出空间或移到下一行；文字不能被截断。整个标题仍向无障碍服务提供完整日期。

## 验收方式

1. 从三个主页面均可进入设置，并可返回原页面；旋转屏幕后不会丢失当前页面。
2. 当前版本、查询中、已是最新、下载中、取消、失败重试和等待安装授权均有可理解的页面反馈。
3. 使用包含预发布版的测试发布列表，验证数值版本比较；旧版、同版、异常标签和缺少 APK 的发布不会触发下载。
4. 用测试文件验证不完整下载、长度与摘要不符、包名/版本号/签名不匹配时不会启动安装器。
5. 使用用户照片对应的日期、屏幕宽度和较大字体检查「星期六」不会拆开换行，同时复查深色模式与其他主页面标题。
6. 运行单元测试、Android Lint、Debug 构建；有真机时验证权限、安装确认、取消安装和覆盖后本地记录保留。没有可用真机时，明确记录该验证未完成。

## 官方依据

- [GitHub Releases REST API](https://docs.github.com/en/rest/releases/releases)：发布列表包含公开预发布版，`latest` 只返回非预发布版。
- [Android 应用更新条件](https://developer.android.com/google/play/app-updates)：包名、签名和版本号必须满足覆盖要求。
- [Android 安装权限](https://developer.android.com/reference/android/Manifest.permission#REQUEST_INSTALL_PACKAGES) 与 [FileProvider](https://developer.android.com/reference/androidx/core/content/FileProvider)：系统授权与安全文件共享。
